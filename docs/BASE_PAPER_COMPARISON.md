Source inspected in full: H. Geng, H. Zhang, X. Shi, Z. Wang, X. Yin, J. Zhang, Z. Hu, Y. Wu, *A Hybrid Link Protection Scheme for Ensuring Network Service Availability in Link-state Routing Networks*, Journal of Communications and Networks 22(1), pp. 46–60, February 2020, DOI [10.1109/JCN.2019.000056](https://doi.org/10.1109/JCN.2019.000056). The user supplied the 15-page PDF in this conversation. **The PDF itself is not committed**: its page 1 says CC BY-NC; obtain an explicit redistribution/licensing decision before bundling it with this Apache-licensed codebase. Page numbers below are the journal's printed page numbers (PDF page = printed page − 45).

## What the base paper actually does

- **Setting (pp. 48–49, Section III):** Connected undirected link-state routing graph, each edge has a cost and statistically independent link failures. The paper defines end-to-end availability using inclusion–exclusion over *multiple forwarding paths* (Eqs. 1–2); `A(G)` is their mean over ordered source–destination pairs (Eq. 3). On failure, the failure-detecting node uses a feasible local alternate or a special-header multi-hop repair path.
- **Stage 1 (pp. 50–55, Section IV, Algorithm 2):** MNP-e adds all next hops satisfying the loop-free criterion using modified shortest-path trees and incremental SPF after changing `(c,x)` to negative cost. The paper asserts both LFC-equivalent coverage (Theorem 8) and less-than-one-SPF complexity (Theorem 7). The actual code's repeated-neighbor Dijkstra is neither this algorithm nor evidence for its timing claim.
- **Stage 2 (pp. 54–56, Section V, Algorithm 3):** For each router `v` and destination `d`, key link `e=(v,B_v(d))` arises when `|N_v(d)|=1`. **Its `e.P` includes `(v,d)`**, *not every upstream `(s,d)` traversing the edge*: the paper explicitly calls this a conservative shortcut to save computation (p. 56). The score is `Δ(e)=Σ_{(s,d)∈e.P}[A*(s,d)−A(s,d)]` (Eq. 6). It derives `A*` by adding a pseudo-link with availability based on the new shortest path in `G−e`, then recomputing inclusion–exclusion on the augmented graph. It sorts key links and stops at `A(G)≥R` or exhaustion. No fixed backup-link budget, demand matrix, or link-capacity objective is part of its formulation.
- **Evaluation (pp. 57–58, Section VI):** Abilene 11/14 and Rocketfuel Exodus 79/147, Telstra 108/153, Tiscali 161/328, Sprint 315/972; BRITE Waxman synthetic graphs (Table 2), generated link failure values from **0 to 0.02**, Intel i5 1.7 GHz / 1.5 GB. Table 3 reports per-node computation time; Table 4 reports network availability. Figs. 13–18 compare HLP with full multi-hop protection and show backup-link overhead versus availability requirement. This is not an intrusion-detection or ML paper.
- **Limits/gap for an extension:** The method does not model OD demand, measured link capacity, post-failure congestion, stale traffic knowledge, or an explicit fixed protection budget. These are reasonable *new questions*, but the base paper already ranks by uneven link failure importance (pp. 46–47); demand weighting alone should not be framed as discovering that links differ in importance.

**Notation caution:** Section III.A (p. 48) calls `r(u,v)` a *failure probability*, while printed Eq. 1 multiplies `r` to obtain a working-path probability. With the paper's generated range `[0,0.02]`, these statements are inconsistent if `r` means failure probability throughout. Treat this as a source ambiguity; explicitly define `p_fail` and `1−p_fail` in our formulation instead of silently copying the notation or asserting without evidence which part of the paper is a typo.

## Immediate implication

The repo's current `compute_hlp()` is a **HLP-inspired comparator**, not a numerical reproduction of Algorithm 2 + Algorithm 3 + Eqs. 1–3/6. Before claiming improvement over Geng et al., either (a) implement a faithful base-paper baseline with the paper's availability evaluator, keyed path sets and i-SPF (or make a carefully justified coverage-equivalent approximation but never compare runtime), or (b) narrow the paper claim to a well-described comparison against a separately named *LFC + greedy-topology proxy* using the exact same simulator and inputs. The second option is faster and honest, but less persuasive as a base-paper advance.
